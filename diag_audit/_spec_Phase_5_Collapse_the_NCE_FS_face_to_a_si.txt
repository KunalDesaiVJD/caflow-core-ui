SUMMARY:
Rewrite the two face memos `nceCyAmounts` (PipelineFinancialStatements.tsx ~3970-4064) and `ncePyAmounts` (~4066-4165) so the NCE Balance-Sheet / P&L face is built from ONE source — the canonical note totals over `nce_financial_notes` (via `getNCENoteFaceTotal`, which already delegates to `computeNoteTotals` in nceNoteTotals.ts) — mirroring Corporate's single `ncyOf` read. The four-layer override stack (Layer0 raw TB + Layer1 legacy `stage5_notes` overlay via `sumNotesSubRowsCY/PY` + Layer2 FA-grid via `getFAGridNetBlockTotal` + Layer3 `nce_financial_notes`) collapses: Layer1 is removed behind a per-engagement migration gate, Layer2 (PPE/Intangibles/CWIP net-block + the manual `fa_financial_statements` face override) is folded into the Phase-1 edit-ledger so it flows through the SAME applied-once path, and the RESIDUAL ABSORBER that silently dumps BS imbalance into `NCE_CAP` (~4040-4046 / ~4145-4151) is deleted so any imbalance surfaces in FsHealthPanel + the export gate instead of being hidden. What stays: the sign convention (`NCE_NOTE_NATURE` flip), the BS_EQ_RS→NCE_CAP profit fold, the NCE_AST/NCE_EL parent recompute, and the P&L parent-total + profit-chain recompute. No DB schema change: the edit-ledger is a JSONB key inside existing `cy_data` (Phase 1), and the legacy `stage5_notes` channel is still READ for un-migrated engagements during the one-release back-compat window.

DEPENDS ON: Phase 1 — the cy_data._edit_ledger dot-path manual-edit ledger (getAtPath/setAtPath/markManualEdit mirror of notesAutoPopulate.ts 1039-1092). Phase 5's FA fold and the single-read collapse consume the ledger via getEditLedger; until Phase 1 lands, applyFaFaceCode falls back to getFAGridNetBlockTotal and the edit-ledger reads empty.

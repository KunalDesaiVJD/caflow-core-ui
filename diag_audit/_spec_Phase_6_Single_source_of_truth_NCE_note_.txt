PHASE: Phase 6 — Single source-of-truth NCE note registry + corporate-twin normalization at COA-mapping save

SUMMARY:
Introduce ONE array of NCE note definitions (NCE_NOTE_REGISTRY) from which all seven scattered registration structures are derived at module load: NCE_NOTE_FS_MAP, NCE_CODE_TO_NOTE, NOTE_NATURE, FS_CODE_NATURE (NCE half), CANONICAL_NCE_CODE, NCE_LIAB_CODE_SET, and (via re-export) the NCE_CODE_TO_NOTE_KEY/NCE_NOTE_NATURE consumers in PipelineFinancialStatements. Each registry entry carries the note's storage key, BS/PL FS code, nature, pattern column (lt/st/none), and an explicit list of legacy corporate twin codes it ACCEPTS. The derivation reproduces the EXACT current contents of every hand-maintained map (verified byte-for-byte against the existing literals) so behavior is unchanged on day one; it is purely a refactor that collapses ~7 edit sites to 1. Separately, add a normalizeCoaCodes() pass invoked once at every COA-mapping save in PipelineStage3.tsx that folds corporate twin codes (BS_CL_STB, PL_EXP_OTH, BS_CL_TP_MSME, BS_NCA_DTA, etc.) to their canonical NCE_* code BEFORE persisting, so newly-saved engagements only ever store NCE_* codes — while the registry continues to accept corporate codes from already-saved engagements.

DEPENDS ON: Phase 1 (manual-edit ledger inside cy_data) — Phase 6 must not disturb the _custom_rows / manual-edits metadata channels Phase 1 adds; both are additive and independent, but Phase 6 should land LAST so registry derivation reflects any note added in Phases 1-5., Phases 2-5 (whatever they register) — any new NCE note introduced by an earlier phase MUST be added to NCE_NOTE_REGISTRY as part of that phase's merge, otherwise Phase 6's parity assertion will fail. Phase 6 is explicitly the hardening pass that lands after all note-adding phases.

  // src/config/nceNoteRegistry.ts
  export type FsNature = 'DR' | 'CR';
  export interface NceNoteFsCode { code: string; /* the canonical/twin FS code */ twin?: boolean; /* true if a corporate twin alias */ }
  export interface NceNoteDef {
    /** storage note_type key in nce_financial_notes (e.g. 'borrowings','trade_payables','cogs'). */
    noteType: string;
    /** natural side of the whole note — drives NOTE_NATURE + nce code nature. */
    nature: FsNature;
    /** Pattern A (lt/st split) vs Pattern B (single 'all' column). */
    pattern: 'A' | 'B';
    /** Pattern B: single fs-code list. Canonical NCE_* code MUST be index 0; remaining entries are corporate twins/aliases the derivation still ACCEPTS. */
    all?: string[];
    /** Pattern A long-term column list — canonical NCE_* at index 0, corporate twins after. */
    lt?: string[];
    /** Pattern A short-term column list — canonical NCE_* at index 0, corporate twins after. */
    st?: string[];
    /** Per-canonical-code overrides for NCE_CODE_TO_NOTE (config sub-note for multi-section notes like cogs->cogs_a/cogs_c). Keyed by FS code. */
    codeToNote?: Record<string, { note: string; col?: 'lt'|'st'; config?: string }>;
    /** Legacy stage5_notes key for NCE_CODE_TO_NOTE_KEY derivation (optional; only for notes that have one). */
    legacyNoteKey?: string;
  }
  /** Equity/capital codes that have a nature but no note mapping (NCE_PCAP/NCE_RES/NCE_NCB/NCE_CAP). */
  export const NCE_EXTRA_CODE_NATURE: Record<string, FsNature>;
  export const NCE_NOTE_REGISTRY: NceNoteDef[];
  // Derivation builders (pure, called at module load by consumers):
  export function deriveNoteFsMap(): Record<string, { lt?: string[]; st?: string[]; all?: string[] }>;
  export function deriveCodeToNote(): Record<string, { note: string; col?: 'lt'|'st'; config?: string }>;
  export function deriveNoteNature(): Record<string, FsNature>;
  export function deriveNceCodeNature(): Record<string, FsNature>; // every NCE fs code (+ extras) -> nature
  export function deriveCanonicalNceCode(): Record<string, string>; // twin code -> canonical NCE_* (index-0 fold)
  export function deriveLiabCodeSet(): Set<string>; // CR-nature canonical NCE codes + equity extras
  export function deriveCodeToNoteKey(): Record<string, string>; // canonical code -> legacyNoteKey
  /** Fold corporate twin codes in a coa_mapping to canonical NCE_* codes. Pure; returns new object; non-twin/unknown codes pass through untouched. */
  export function normalizeCoaCodes<T extends Record<string, any>>(mapping: T): T;
  /** Dev-only parity guard against frozen legacy snapshots. */
  export function assertRegistryParity(): void;
